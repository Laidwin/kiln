Kiln ships a reusable GitHub Actions workflow that builds your site with the Kiln image and deploys it to GitHub Pages.

<Steps>

1. In your repository, open **Settings → Pages** and set **Source** to **GitHub Actions**.

2. Add this workflow:

   ```yaml title=".github/workflows/docs.yml"
   name: Docs

   on:
     push:
       branches: [main]
     workflow_dispatch:

   permissions:
     contents: read
     pages: write
     id-token: write

   jobs:
     docs:
       uses: Laidwin/kiln/.github/workflows/pages.yml@v1
   ```

3. Push. The site is published at `https://<owner>.github.io/<repo>/`.

</Steps>

## Python API reference

For a Python project with `api.python` in `docs.yml`, the workflow generates the JSON file with griffe before building:

```yaml title=".github/workflows/docs.yml"
jobs:
  docs:
    uses: Laidwin/kiln/.github/workflows/pages.yml@v1
    with:
      python-package: my_package   # several packages: "pkg_a pkg_b"
      python-path: src             # folder containing the package
      python-docstyle: google      # or numpy, sphinx
```

The file is written to `api.json` (input `python-output`), next to `docs.yml`. See [Adding an API reference](/guides/api-reference/).

## Base path

GitHub Pages serves project sites under `/<repo>/`. When `docs.yml` has no `base`, the workflow derives it from the repository name, so internal links work without any configuration. Set `base` explicitly for a custom domain:

```yaml title="docs.yml"
base: /
site: https://docs.example.com
```

## Versions

`@v1` follows every compatible release of Kiln. Pin `@v1.2` to receive only patches, or `@v1.2.3` for a fully reproducible build.

## Other hosts

`kiln build` writes a plain static site into `site/`. Any static host works: Netlify, Cloudflare Pages, S3, nginx…

```sh
docker run --rm -v "$PWD":/project -e KILN_BASE=/docs ghcr.io/laidwin/kiln build
```
